# Входящие списки, согласование и результат для заказчика

## 1. Довести существующий импорт

Расширять ImportDialog, lib/imports.ts, files.ts и Python parser. Не создавать второй загрузчик, теряющий нынешние mapping, sheet selection, safe parsing, sourceRow, повторный ImportBatch и отчёт исключений. Новый путь: выбрать файл/вставить диапазон → выбрать лист/заголовок → сопоставить колонки → указать профиль/набор/событие → предварительная проверка → подтвердить применение в черновик.

Табельный номер, внешний ID и номера документов — текст, с ведущими нулями. Даты — строго date-only, Excel serial интерпретируется по поддерживаемому формату и системе дат, без UTC сдвига. Пустая ячейка не равна «стереть старое»: это задаётся режимом обновления. Формулы не вычислять; безопасно объяснять необходимость вставить значения. CSV/TSV учитывать BOM, quoted separators, переносы строк; не ломать фамилии с дефисом/апострофом. Имена не переводить автоматически.

Неподдерживаемые макросы, внешние ссылки, ZIP/XML bombs и слишком большие файлы отвергать ограниченно и понятно. Ограничение 100 строк в одной рабочей заявке сохранить, пока не измерена и не согласована иная граница. На 101 строке — явный выбор/разбиение на связанные заявки в рамках заказа, без потери остатка. Разбиение списка не является разрешением менять число фактических протоколов: группы должны соответствовать реальным событиям.

## 2. Обновлённый список

Сопоставление: устойчивый ID человека/согласованный внешний ключ, затем табельный номер внутри работодателя/актуального периода. ФИО и должность — кандидаты для проверки, не автоматический merge. Все неоднозначности показываются.

Результат сравнения содержит sourceRow, целевую строку/personId, совпавший ключ и категории added/changed/unchanged/missing/ambiguous. Для changed — old/new/источник по каждому полю. Оператор выбирает field mask и строки. Индивидуальные результаты и назначения не перезаписываются из общего списка сотрудников без отдельного режима и подтверждения.

missing по умолчанию не удаляет ни человека, ни участие, ни историю. Можно явно исключить из неоформленного состава, указав причину. Уже оформленные данные не изменяются; предлагается процедура исправления/новое событие. Применение выполняется транзакционно с expectedRevision и operation key; отчёт сохраняется без лишней копии ПД в логах.

Fixture revised содержит 2 новых человека, 3 изменённые записи, 2 отсутствующие записи и 95 неизменённых. Автоприменение с политикой retain missing оставит 102 записи и нарушит лимит заявки: система должна потребовать выбор/исключение отсутствующих из текущего черновика, а не тихо обрезать. После явного исключения этих двух из текущей заявки итог 100. Их карточки и история сохраняются. Точные ключи в EXPECTED_FIXTURES.json.

## 3. Быстрый обмен с заказчиком

Контрольный лист — компактная таблица значимых переменных сведений всего заказа с источником/версией. Заметная отметка: «Данные для проверки — не выданный документ». Он не расходует номера и не является preview 100 отдельных удостоверений. Форматы: защищённая страница и выгрузка PDF/XLSX по согласованному составу; добавить повторно используемые средства рендера, не зависеть от браузерной печати для канонических удостоверений.

Подтверждение привязано к hash значимых данных и идентификатору подтвердившего. Изменение ФИО, работодателя, программы, дат или состава делает подтверждение устаревшим; изменение внутренней заметки не должно молча считаться новым согласованием. Подтверждение контрагентом — запись о сверке, не ЭЦП, не экзамен и не перенос ответственности за правильное оформление.

Команда «Запросить уточнения» готовит редактируемое сообщение по текущим ошибкам. Показать исходные номера строк/табельные номера, но не внутренние UUID/stacktrace. Копирование текста — полноценный рабочий результат без WA/SMTP. Внешняя отправка не происходит автоматически. Внутренние проблемы шаблона/БД адресуются оператору/администратору, а не заказчику как «неправильно заполнен список».

## 4. Профиль реестра

Customer profile определяет ограниченный перечень разрешённых полей, заголовки, порядок, сортировку, представление «строка на назначение» или «строка на сотрудника с колонками направлений», формат дат и язык. Второй вид допускается только при однозначных значениях; несколько событий в одной ячейке не склеивать с потерей номера/даты — предложить подробный вид.

В первую поставку не нужен механизм редактирования произвольного исходного XLSX с любыми формулами/дизайном. Создавать новый корректный реестр; оригинальные номера строк и табельные номера сохраняются. Clipboard export — TSV безопасных значений с тем же порядком.

Групповой протокол отражается как один документ и как ссылка в строках участников; не считать повторение его номера в 100 строках 100 регистрациями. Номера BIOT worker/ITR берутся из общего resolver. Выгрузка согласованного набора производится на сервере, не по видимой странице и не по текущим изменённым справочникам для исторических выпусков.

Формульная безопасность: значения, начинающиеся с =,+,-,@ и управляющих пробелов, безопасно экспортируются в текстовые ячейки/CSV. Защита применяется к экспорту, а не тайно меняет настоящее ФИО в базе. Числа и даты, которые должны быть вычисляемыми, обрабатываются отдельно от пользовательских строк.

## 5. Имена и комплект выдачи

Примеры шаблона имени: «табельный номер — ФИО — тип — номер»; безтабельный вариант «ФИО — тип — номер». Служебный stable suffix добавляется при коллизии имён. Удалять запрещённые символы путей, резервные Windows имена, traversal, управляющие символы; сохранять читаемость RU/KZ, лимит длины пути и детерминированность. Не использовать ИИН в имени по умолчанию.

Папки: плоско / по человеку / по направлению / по подразделению. Ограничить настройки понятными вариантами. Состав пакета: разрешённые документы, реестр, опись и сопроводительный текст. Опись содержит ожидаемое/готовое/отсутствующее и checksum готовых bytes. Переименование архива не меняет байты канонического документа или записи Artifact. Имя download/ZIP member допустимо вычислить по сохранённому delivery profile.

Повторная печать выбирает сохранённые файлы. «Восстановить» — отдельная процедура при утрате. Если ни один выбранный файл не готов, не выдавать пустой ZIP как успех. Сбой одного формата показывает точный остаток и повтор только неудачных заданий. Результат рассчитан на передачу, а не нуждается в ручном переименовании оператором.
