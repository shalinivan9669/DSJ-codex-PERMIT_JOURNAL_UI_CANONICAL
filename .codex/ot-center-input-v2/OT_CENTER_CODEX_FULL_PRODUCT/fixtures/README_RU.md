# Синтетические данные для воспроизводимой приёмки

Все люди/организации/результаты вымышлены. Это **не production seed**, не удостоверения и не юридическое основание. Все артефакты обязательны с watermark «ДЕМО — НЕ ЯВЛЯЕТСЯ ВЫДАННЫМ ДОКУМЕНТОМ» в отдельном demoOnly tenant. Нельзя импортировать в рабочую БД. Паролей, реальных ИИН, подписей и шрифтов нет.

`100_people.xlsx` содержит лист «Сотрудники» с заголовками в первой строке и лист инструкции. CSV/TSV/JSON содержат тех же 100 человек. Они не несут номеров выдачи и положительных результатов. Все даты в JSON/CSV — ISO date-only. Табельные номера «000001» и другие должны оставаться текстом. Два одинаковых ФИО с ключами P009/P010 — разные люди.

`100_people_revised.*` — исправленный список; EXPECTED_FIXTURES.json задаёт 2 новых, 3 изменённых, 2 отсутствующих и 95 неизменённых. Отсутствие в файле не разрешает удалять историю. При retain missing будет 102 строки: ограничение одной заявки 100 требует явного решения до применения.

`training_events.json`, `issuer_and_customer.json` и `results_G1/G2.*` отделяют общие данные от персональных. Ведомость результатов импортируется отдельным подтверждённым действием только на тестовом стенде. Значения PASSED не являются начальными значениями продукта. Часы/сроки в fixture — вход теста существующих контрактов, не правовая рекомендация.

Идентификаторы DEMO-* являются устойчивыми ключами **передачи**, а не готовыми Prisma UUID. Исполнитель создаёт небольшой адаптер fixture→актуальные API/схемы, хранит mapping исходных ключей и не делает bypass production guards. Адаптер проверяет имя disposable DB, demoOnly tenant и прекращает работу при несовпадении. Подтверждение synthetic шаблона не даёт полномочий реальному центру.

Для G1 используется только PB-G1 и results_G1. Для G2 — PB-G2/PTM-G2/BIOT-G2 и results_G2. Каждый golden сценарий запускается в отдельном чистом тестовом наборе; общий подсчёт не должен включать старые выпуски, previews, контрольные листы и derivative ZIP. Счётчики сравниваются до/после, не предполагается старт с единицы.

В `negative_variants.json` каждый вариант применяется отдельно к чистому исходному сценарию. Строка `=1+1` — безопасный тест формульной инъекции, её нельзя записывать в XLSX как формулу. Фото взять из существующего synthetic fixture репозитория только там, где требует форма, не использовать реальные лица.

## Повседневные сценарии версии 2026-09-22.2

`DAILY_WORKFLOWS.json` содержит небольшие отдельные случаи V01–V12: один человек, три человека, шесть и восемь участников, повторный заказ, работа заказчика и руководителя. Это не дополнительные нормативные данные и не готовый seed. Внешние состояния создаются только в disposable demo-only tenant. Синтетические результаты хранятся отдельно от данных людей и применяются явно.

Большой набор G1/G2 сохранён без изменения: он проверяет объём и корректность, а не определяет весь продукт.
