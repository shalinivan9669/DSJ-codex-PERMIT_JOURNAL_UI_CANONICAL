КОНФИГУРАЦИЯ ЗАПУСКА — 15.10.2026

Пакет предназначен для выбранной пользователем GPT-6 Astra либо GPT-6.1 Sol. Это отдельные модели. Конкретный выбор делается в Codex до запуска; текст задания не переключает текущую модель, не изменяет глобальные конфигурационные файлы и не обходит лимиты аккаунта.

Локальные метаданные инструментов этого приложения в момент подготовки объявляют gpt-6-astra и gpt-6.1-sol и уровни low/medium/high/xhigh/max/ultra. Поэтому для требуемой максимальной глубины можно выбрать Ultra, если он доступен в селекторе данной модели. Если интерфейс предлагает Max как максимум — выбрать Max. Селектор конкретной среды является фактическим источником доступности, а не этот текст. Разрешения на ресурсы/внешние действия от уровня рассуждений не меняются.

Публичная API-страница GPT-6.1 Sol перечисляет reasoning.effort low, medium, high, xhigh, max; это не доказательство существования API-значения ultra. Не передавать ultra в API только потому, что такая настройка заявлена локальным Codex. В задании нет API-интеграции с OpenAI и не требуется ключ OpenAI.
Источник, открытый при подготовке: https://developers.openai.com/api/docs/models/gpt-6.1-sol

Для длительного задания полезны ясная граница результата, явно заданная автономность, ограниченное распределение файлов между субагентами и проверка результата. Главный промпт определяет это без повторной загрузки всей истории и без требования читать все ресурсы перед каждым редактированием. Настоящий результат оценивается по выполненным критериям, а не по названию модели.
Источники, открытые при подготовке:
https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.1-sol
https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra

Настройки роя: координатор и до трёх субагентов одновременно по доступности среды; наследовать выбранную конфигурацию, если пользователь отдельно не поручил иное. Координатор интегрирует общие schema/contracts/auth, агент API и агент UI работают параллельно по согласованным файлам, независимый проверяющий проверяет собранный результат. Больше агентов без изоляции файлов не означает более быстрый или качественный результат.

Пакет не гарантирует, что любой объём работы физически поместится в один лимит выполнения. Он устраняет обязательные ручные перезапуски между функциональными фазами, сохраняет RUN_STATE для продолжения после сжатия/прерывания и запрещает сокращать согласованный объём ради объявления успеха. Внешние доступы, утверждённый учебный контент, полномочия и действительные подписи создаются не моделью.
