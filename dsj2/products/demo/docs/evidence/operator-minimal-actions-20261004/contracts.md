## Изменение и сохранность

- В `business-rules.ts` единый `businessValidity`/`applyBusinessValidity` применяется нормализатором и `resolution.ts`. Календарная арифметика вынесена из дублирующего расчёта в `calendarAnniversary` в `biot.ts`; 29 февраля ограничивается последним днём февраля конечного года. Старые категорийные сроки сохраняются для legacy без LIVE_V1. Общее правило центра не объявляется актуальной нормой закона; расхождение особых категорий ИТР явно остаётся в UI.
- В LIVE_V1 стадия вычисления периода больше не подставляет конкурирующий категорийный срок перед общим правилом. Ручные/импортированные даты, явная очистка и старые manual flags защищены в обеих стадиях, в том числе для общих profile/preset/request/event полей.
- Общие фактические оценки и квалификации допускают персональные исключения в групповом протоколе; `eventProtocolAssignment` не затирает их общими значениями. Явная несдача, неявка или ожидание не наследуют положительный общий текст оценки.
- В UI разрешено редактировать явный срок и вернуть AUTO; выданный документ остаётся заблокирован через `documentDisabled`. Убраны устаревшие заявления «ручной срок не предусмотрен».
- Новые отрасль, баллы, внешний прокторинг, имена, номера и графики не выдуманы. Исторические payload/snapshot не мигрировались, БД и runtime этим подзаданием не изменялись.

## Оставшийся обязательный ввод и график

Существующий профиль центра уже хранит `commonFields.trainingDateRule`, а resolver наследует его новым заявкам. Для одинаковой программы достаточно один раз выбрать фактический график курса/центра; тест подтвердил автоматическое применение ко всем формам без личной настройки. Если профиль не содержит подтверждённого графика, программа не может достоверно вывести период из одних часов. Аналогично, реальные отрасль, числовая оценка или факт прокторинга должны поступать из выбранной программы/достоверного ввода. Видимый общий курс-контекст реализуется головным агентом; данный подрезультат добавляет его контракт и разрешение источников.

## Дополнительные пути новой обычной заявки

Проверка кода обнаружила пустые результат/часы/дату у `repeatDraft` и принятого обращения работодателя `REPEAT_REQUEST` в `apps/api/src/operator-value.ts`. Исправлено: новые повторные заявки используют свежие стандартные PASSED/result с AUTO/COURSE provenance, часы выбранной категории, schemaVersion=2, общую текущую дату в timezone tenant и актуальную версию профиля. Исторические оценки RU/KZ/EN, знания/прокторинг, номера и подтверждения в новую попытку не копируются. Исходная история неизменна; коррекция выпущенного документа и специальная пересдача UNKNOWN остаются отдельными путями.

Принятый повтор через портал теперь переотображает каждый исторический eventId на свой новый UUID. Два курса одного направления и одинакового названия остаются двумя событиями; связанные карточка/протокол одного события остаются одним комплектом. В новое событие допускается только текст программы/отрасли/профессии; старые даты и общие оценки не перенесены.
