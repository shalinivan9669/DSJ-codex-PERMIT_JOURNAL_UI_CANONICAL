## Фактические источники переданного документа

| Данные | Источник и правило проверки |
| --- | --- |
| ФИО, должность, индивидуальные исключения | Переданный `RequestProposal.payload`, выбранный состав; отдельные языковые написания не выдумываются |
| Организация, БИН, адрес | Замороженные `organizationSnapshots`; `employerFields` дополняет только совпадающего/явно выбранного работодателя, конфликт БИН останавливает fallback |
| Программа, часы, даты | `resolveDraft` над переданным payload + закреплённая версия профиля; возвращается provenance COURSE/CENTER/REQUEST/EVENT/MANUAL/IMPORTED/AUTO/CLEARED |
| Результат | Индивидуальный outcome/result и его исходный источник; решение директора не создаётся default-значением |
| Готовность | Та же `validation` / `validateDraft`, что используется перед передачей и подготовкой печати; отдельный старый payload проверяется самостоятельно |
| Preview | Существующий endpoint preview, явные proposalId + expectedProposalHash; реальные образцы из immutable состава и полные общие протоколы |
| Пересдача | Новая копия попытки с `retakeOf`; результат UNKNOWN, прошлые результаты/оценки RU/KZ/EN, даты, номера, notes и их provenance очищены; программа и защищённые часы сохраняются |

## Изменения

- Директор видит короткую сводку людей, обучений, effective дат, часов, результатов и источников. Полный состав раскрывается отдельно. Исходный diff сохранён во вторичном раскрываемом разделе.
- PDF запускается одной кнопкой из согласования: один реальный получатель для каждой формы/обучения/категории, общие протоколы содержат весь переданный состав. UI явно называет эти документы образцами. PDF открывается существующим `PdfPreview`; это не выпуск и не резервирование номеров.
- Preview привязан к hash переданной редакции; изменённый рабочий черновик не подменяет его. Новые preview snapshots/jobs имеют отдельный logicalKey с proposal hash. Исторические payload/hash/выпуски не переписываются.
- Неполная старая редакция показывает замечания и явное возвращение для проверки актуального черновика. При недоступной исторической ссылке detail остаётся доступным, а approval закрыт до серверной проверки. Самостоятельного повышения UNKNOWN и подмены личных данных нет.
- Передача и решение проверяют effective значения. Решение дополнительно проверяет сам переданный payload, даже если текущий черновик уже исправлен.
- Баннер менеджера читает состояние PENDING/APPROVED каждые 6 секунд только в видимой вкладке, а также при возврате фокуса. Parent refresh вызывается лишь при изменившейся revision/decision/hash/request status и использует существующий flush/reload для сохранности ввода.
- У работодателя без явной связи имя должно совпадать с компанией; БИН не должен противоречить ей. Ручной чужой работодатель и одиночный адрес неизвестной компании больше не получают БИН/адрес заказчика.
- Пересдача очищает все поля предыдущей попытки и их origins как у назначения, так и у общих полей события; старые lineage caches не переносятся в новое событие.
