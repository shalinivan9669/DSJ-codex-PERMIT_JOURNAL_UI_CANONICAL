# Автозаполнение и действительные поля печати — 05.10.2026

Область: автономный DEMO; 11 индивидуальных и 5 групповых форм текущей NEUTRAL_FORMS_V1. Матрица сопоставляет проверку, разрешение значений, snapshot и действительный mapper, а не только устаревающий список `fields` в manifest. Дополнительно зарегистрированы три явных варианта существующих специальных форм ИТР. Это инженерный контракт продукта; документ не устанавливает правовые требования и не подтверждает физическую печать.

## Общая цепочка данных

`COURSE → CENTER → PRESET → REQUEST → EVENT → индивидуальное исключение` задаёт источники общих значений. `MANUAL`, `IMPORTED`, `CLEARED` имеют приоритет; техническая пустая строка без осознанного происхождения не затирает нижележащий источник. Сервер повторяет разрешение значений. Рабочий draft сохраняет значения и происхождение, явная передача фиксирует согласуемый состав и разрешённые значения, выпуск использует immutable snapshot, точную версию/хеш шаблона и связанные внутренние номера. Изменение справочника после передачи требует новой передачи; оно не должно менять согласованный документ.

## Явные SPECIAL-варианты ИТР

| Назначение | Registry version | Неизменяемый источник | Что устраняет разрыв |
|---|---|---|---|
| Индивидуальный сертификат | `special-14-1` | `biot-itr-certificate.v14.docx`, SHA-256 `ee6a5e8089d63fdcf1755259c8acb52aac8e8a23a7fed1d6025781aee2505e7c` | Печатает отрасль RU/KZ, часы, имя, результат, дату/срок, номер и руководителя |
| Индивидуальный протокол | `special-1-1` | `biot-itr-protocol.v1.docx`, SHA-256 `4ee4d6be0dde0511da26178dad0a01fad08228cd898c4b865b4df9aae45cdc29` | Печатает БИН/название/адрес работодателя, knowledge/proctoring, уникальный/связанный номер, должность, результат |
| Групповой протокол | `special-1-group-1` | Те же неизменённые bytes v1 + действующий `groupContractVersion=1` | Настоящая групповая таблица со своими обязательными сведениями каждого участника |

Выбор сервера ключуется по `templateId` и `program=SPECIAL`, отдельно для ownerKind GROUP. Поэтому более поздняя регистрация специальной версии не заменяет ordinary форму; наличие только ordinary версии не позволяет обойти SPECIAL-проверки. Старые snapshots продолжают использовать прежние templateStorageKey/checksum и renderer. Регистрация новых ссылок append-only, сначала `approved=false`; утверждение выполняется существующим директорским endpoint. Миграции/перезапись старых версий не требуются.

## Проверка

Свежие точные результаты и хеши: `render-readback.json`, `special-render-readback.json`, итоговый отчёт браузерного цикла этой задачи. DOCX/PDF renderer-тесты доказывают сохранение данных и конвертацию. Они сами по себе не доказывают UI-автозаполнение, фактический пользовательский результат, Microsoft Word/физическую печать или правовое утверждение форм.

Основные исходники: `packages/contracts/src/{index,business-rules,course-defaults,resolution,date-calculation}.ts`, `apps/api/src/{requests,template-selection}.ts`, `scripts/render/{renderer,neutral_forms,neutral_certificates,legacy_snapshot_fields,biot_2026,group_protocol}.py`.
