## Почему недостаточно обновить пакеты старого образа

Исходный `postgres:18.3-bookworm` имел 134 находки HIGH/CRITICAL в фактическом отчёте Trivy. Обновление до PostgreSQL 18.6, обновление Debian-пакетов и удаление неиспользуемого `gosu` сократили число до 93. Для оставшихся находок выполнен поштучный разбор в `container-postgres-bookworm-triage.json`. Ограничения контейнера не названы исправлениями библиотек: 44 находки остались открытыми для анализа достижимости, 41 получила только описание мер ограничения, восемь не применимы к фактической архитектуре или отсутствующим компонентам. Этот вариант не прошёл критерий отсутствия неразрешённых HIGH/CRITICAL.

Официальный Alpine-вариант 18.6 дал ноль OS-находок, но сохранил 22 HIGH/CRITICAL в `gosu`. Отсутствие libxml2-находок в этом отчёте не принято за доказательство исправления: рецепт Alpine и его secdb не учитывали все свежие upstream CVE. Сохранены фактический отчёт и копия secdb. Поэтому предложена сборка с полным исключением ненужной DEMO зависимости libxml2, а не исключением её находок из отчёта.

## Выбранная сборка

`deployment/Dockerfile.postgres` собирает PostgreSQL 18.6 из официального архива с SHA-256 `555610c24d53e4316da5b7d3fc25c279d96856d5e0e23ee308c328c5fa881d9f`. Сборочный и конечный Alpine 3.24.2 закреплены digest; два entrypoint-скрипта берутся из закреплённого официального `postgres:18.6-alpine`. Параметры `--without-libxml --without-libxslt` являются штатными параметрами upstream. Сохранены ICU, OpenSSL, libedit, LZ4, Zstandard, обычные реляционные типы, JSONB и PL/pgSQL. Не включены дополнительные PL/Perl, PL/Python, PL/Tcl, LLVM JIT, LDAP и GSS; DEMO не использует их. SQL/XML отсутствует намеренно, с явной проверкой ожидаемой ошибки `feature_not_supported`.

Это конфигурация PostgreSQL из официального исходного кода, а не утверждение о поддержке кастомного образа командой Docker Official Images. Не применяются подмена SONAME, сторонние двоичные библиотеки или нерассмотренные патчи. Обновление ветки PostgreSQL требует нового проверенного архива и SHA, повторной сборки, upstream regression, миграций продукта, восстановления резервной копии и нового сканирования.

В конечном образе процесс работает как `postgres` (UID/GID 70), файловая система read-only, capabilities удалены, действует `no-new-privileges`. Инициализация требует свежего тома, принадлежащего этому UID. Для проверки создаются только `demo-security-pg186-no-xml` и базы `demo_test_pg186_no_xml*`. Том предыдущего Debian-варианта UID 999 не подключается к новой сборке. Перенос существующей установки требует логической резервной копии и восстановления в отдельный том с повторной проверкой колляций: libc меняется с glibc на musl, новая база использует ICU.

## Границы доказательства

Trivy проверяет распознанные пакеты и библиотеки конечного образа. Сборка PostgreSQL из исходного кода не обязательно распознаётся как пакет менеджера ОС; версия сервера, SHA архива и первичные security release notes проверяются отдельно и фиксируются в provenance. Ноль находок сканера сам по себе не является доказательством отсутствия всех уязвимостей. Старые отчёты сохранены и не подменены результатом нового образа.

Исполняемая проверка зафиксирована в `scripts/verification/postgres-no-xml-smoke.sh`. Финальный запуск использовал отдельные контейнер/сеть/том `demo-security-pg186-no-xml-b`; они сохранены, контейнер остановлен. Предыдущие неудачные bootstrap-запуски сохранены отдельными логами: сначала отсутствовал build-only Perl, затем timezone data в стадии upstream tests, затем потребовалось явно примонтировать исключённую из release image папку integration tests. Эти ошибки устранены и не отмечены как успешные проверки. В финальном smoke `apk info` пытался прочитать сетевой индекс в закрытой сети; список установленных пакетов и весь smoke завершились успешно. В воспроизводимом скрипте для этого read-only запроса теперь явно установлен `--no-network`.
