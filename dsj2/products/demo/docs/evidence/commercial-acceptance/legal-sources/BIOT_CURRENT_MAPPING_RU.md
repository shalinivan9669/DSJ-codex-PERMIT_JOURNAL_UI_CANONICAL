# BIOT: карта обновления по приказу №223 от 30.05.2026

Состояние: read-only сравнение; активные assets не изменялись. Сравнены worker v15,
ITR v13, protocol v9 с официальными RU/KZ PDF. Это проект реализации, а не
подтверждение полномочий эмитента или замена обязательных процедур ЕЦС.

Источники: [официальный RU PDF](https://zan.gov.kz/api/documents/225864/rus/download/pdf),
[официальный KZ PDF](https://zan.gov.kz/api/documents/225864/kaz/download/pdf).
RU: приложение1 стр29, приложение3 стр31–32, приложение4 стр33, приложение12
стр47–48. KZ: соответственно стр28,30–31,32,47–48. Страницы RU47–48 дополнительно
просмотрены как изображения: приложение12 содержит **10** колонок, не7.

## Категории и выбор формы

| Категория | Применимая ветка в ограниченной локальной печати |
| --- | --- |
| WORKER | Удостоверение приложение4 + протокол приложение3, семь колонок |
| OHS_SPECIALIST_SPECIAL, INSPECTOR_SPECIAL, COUNCIL_SPECIAL | Сертификат приложение1 + протокол приложение12, десять колонок; п37 допускает бумажную/электронную форму в обучающей организации |
| MANAGER_GENERAL, OHS_HEAD_GENERAL, INSPECTOR_GENERAL, COUNCIL_GENERAL | Общие компетенции: иной маршрут ЕЦС/ЕУМЦ и приложение2; нельзя печатать приложение1 под тем же названием и объявлять его сертификатом ЕЦС |

Периодичность не является универсальным правилом «все ИТР три года». П5: рабочие
не реже раза в год. П27: general руководители16ч/3года, руководители ОТ40ч/3года,
инспекторы24ч/3года, председатели совета24ч/срок полномочий. П28: special
специалисты40ч/3года, инспекторы40ч/год, председатели40ч/срок полномочий.
П12: обучение рабочих включает теорию не менее10 академических часов и
производственное обучение не менее16 часов; одно общее hours=16 не доказывает
выполнение обеих частей. Эти значения следует использовать как явные presets и
валидацию выбранной категории, сохраняя пользовательские введённые даты.

## Приложение4: удостоверение рабочего

Обязательные смысловые блоки: название удостоверения об экзамене по правилам,
нормам и инструкциям БиОТ; ФИО; успешно оконченная программа; председатель
(должность, ФИО), два члена комиссии (должности, ФИО), подписи; город;
регистрационный номер; дата; М.П. RU. Сохранить требуемую пользователем верхнюю
полосу с RU/KZ названием эмитента как читаемый блок внутри рамки.

Уже есть данные: FULL_NAME_RU/KZ, SUBJECT, issuer.commission[0..2], CITY_RU/KZ,
DOCUMENT_DATE, REGISTRATION_NUMBER/item.number. Текущий worker15 использует
protocolDate вместо даты выдачи, NUMBER вместо отдельного регистрационного поля,
в основном блоке нет полной комиссии/города; исторические повторные панели не
являются заменой полей приложения4. Нужен новый immutable worker16 со всеми
полями. Не вписывать часы/срок вместо отсутствующего нормативного блока; срок
следующей проверки допустим как отдельная служебная информация, не изменение
названия нормативного поля. Устаревшую повторную геометрию нельзя считать частью
официального приложения4 только потому, что она была в историческом бланке.

## Приложение1: сертификат специальных компетенций

| Нормативное поле | Данные / изменение |
| --- | --- |
| Наименование обучающей организации | issuer.nameRu/nameKz уже есть |
| Уникальный номер | item.number уже есть; формат и полномочия выдачи не приравнивать к ЕЦС |
| ФИО | fullNameRu/fullNameKz уже есть; текущий ITR13 подставляет только RU |
| Программа специальных профессиональных компетенций | точная нормативная формулировка RU/KZ; trainingSubject можно сохранять дополнительно |
| Часы | assignment.hours уже есть, в ITR13 отсутствует |
| Отрасль | отсутствует: предлагаем assignment.biotIndustryRu/biotIndustryKz |
| Результат проверки | assignment.result уже есть |
| Дата выдачи, срок действия | documentDate/validUntil уже есть; validUntil в ITR13 отсутствует |
| Город | cityRu/cityKz уже есть, текущий шаблон толькоRU |
| ФИО руководителя обучающей организации | предлагаем issuer.headName; не подменять произвольно CHAIR с должностью |
| Подпись и М.П. | пустые физические места, никаких изображений подписи/печати |

П38 говорит, что председатель комиссии специальных компетенций — руководитель
обучающей организации. Это требование к фактическому составу комиссии, а не
основание молча переименовать любого сохранённого председателя в руководителя.

## Приложение3: протокол рабочих — 1..7

| № | Колонка RU | Предлагаемая модель |
| --- | --- | --- |
| 1 | №п/п | локальный порядковый номер получателя; индивидуальный документ=1 |
| 2 | Наименование организации | item.workplaceRu/Kz, существующий fallback customer.nameRu/Kz |
| 3 | ФИО экзаменуемого | fullNameRu/Kz |
| 4 | Профессия (должность) | positionRu/Kz |
| 5 | Участок, цех, подразделение | новые item.departmentRu/departmentKz |
| 6 | Отметка о проверке знаний | assignment.result; не номер документа |
| 7 | Примечание | новое assignment.biotNotes или оставить явно пустым при отсутствии значения |

Над таблицей: организация, название рабочей категории, protocolDate, состав
комиссии с должностями и ФИО, основание приказа (approvalBasis уже есть),
вид проверки «периодический, повторный» (новое assignment.biotCheckType).
Под таблицей — ФИО и подписи председателя/двух членов, М.П. Существующий protocol9
не только N6: колонки ФИО/организации имеют другой порядок; нет подразделения и
вида проверки. Простое добавление седьмого пустого столбца недостаточно.

## Приложение12: протокол специальных компетенций — 1..10

| № | Колонка RU | Предлагаемая модель |
| --- | --- | --- |
| 1 | №п/п | локальный порядковый номер, индивидуальный=1 |
| 2 | БИН предприятия | новое item.employerBin, fallback customer.bin; не issuer BIN |
| 3 | Наименование и адрес предприятия | workplaceRu/Kz + новые item.employerAddressRu/Kz; fallback customer.addressRu/Kz |
| 4 | ФИО | fullNameRu/Kz |
| 5 | Должность | positionRu/Kz |
| 6 | Уникальный номер | новое assignment.biotUniqueNumber либо явно связанный сертификат; не номер протокола/ordinal и не выдуманный ЕЦС код |
| 7 | Результат проверки знаний | новое assignment.biotKnowledgeResult (балл/процент/фактический результат), отдельно от сдал/не сдал |
| 8 | Результат прокторинга | новое assignment.biotProctoringResult; не генерировать «прошёл» по умолчанию |
| 9 | Отметка сдал/не сдал | существующее assignment.result |
| 10 | Примечание | assignment.biotNotes, пусто если не введено |

Над таблицей: issuer.name, номер протокола, **новый issuer.bin**, точное название
категории из biotCategory, hours, protocolDate, комиссия, approvalBasis,
biotCheckType. Под таблицей ФИО/подписи комиссии. Ширина10 колонок требует новой
геометрии с читаемым шрифтом, предпочтительно A4 landscape; размер/ориентация не
должны определяться случайным двухстраничным разрывом опубликованного PDF.

В RU приложение12 col6 указывает «HS-БИН ОО/номер п/п», в KZ —
«ERM/LHS-БСН/курстың аяқталу күні/тіркеу нөмірі». Также KZ заголовок таблицы имеет
редакционные неоднозначности. Сохранить точные источники и явно согласованное
значение; не объявлять автогенерацию местного номера реализацией реестра ЕЦС.

## Минимальный технический план после согласования имён полей

1. Contracts/API сохраняют biotCategory, отрасль, подразделение, БИН/адрес
   предприятия, результаты и вид проверки; issuer BIN/headName отдельно. Новые
   поля входят в immutable snapshot и CSV/XLSX. Повторный выпуск прежнего snapshot
   использует его прежний template version, без миграции выданных bytes.
2. Сохранить десять логических template IDs. Для `biot-protocol` предпочтительно
   один новый pinned DOCX с двумя явно размеченными секциями WORKER/SPECIAL:
   renderer удаляет невыбранную секцию до подстановки. Один SHA фиксирует обе
   структуры, категория уже входит в snapshot. Альтернатива — variant manifest
   с двумя отдельными pinned assets; она требует расширения provision/health и
   проверки всех checksum. Нельзя выбирать незакреплённый файл по живому каталогу.
3. Новые BIOT worker/ITR assets с точными RU/KZ формулировками, читаемой полосой
   эмитента, >=8pt; никакой перенумерации/переписывания historical originals.
4. Тесты DOCX 1..7 и1..10 по ячейкам, literal numbering без numId наследования,
   повтор на физических страницах, реальные отрицательные mutations, независимые
   поля результатов/номеров, category dispatch и preflight до выдачи номера.
5. Реальная короткая/длинная/batch матрица обеих категорий, Word и LO; stress
   1/2/3/10/13/50/100 отдельно для обеих protocol branches. Прежние96 являются
   evidence исторической версии; новая матрица должна назвать изменённую область.

До нормативного обновления текущий N6 остаётся известным FAIL. После корректного
обновления этот структурный FAIL можно закрыть фактической проверкой N7/N10,
сохранив отдельно отсутствие утверждения эмитента/процедур ЕЦС/физического принтера.
