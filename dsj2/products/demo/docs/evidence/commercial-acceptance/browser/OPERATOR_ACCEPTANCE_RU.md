Область: `products/demo/apps/web`. Проверки выполняются настоящим Chromium/Chrome через Playwright, с действующими Next/Nest/PostgreSQL/Python/LibreOffice и синтетическими пользователями. Существующие localhost:3100/4100 и их данные не изменялись. Web: localhost:3200, API:127.0.0.1:4200, БД `demo_test_browser_commercial_20260922` на PostgreSQL:55432; приватные файлы `.runtime/commercial-browser/artifacts`. Временная сборка `.next-commercial` отделена от исходного preview.

В БД применены миграции 001–005 и выполнен обычный безопасный setup. Повторный setup добавил восемь новых версий v5 и сохранил прежние v4 и оформленные контрольные документы. В настройках поэтому видны 18 версий десяти форм. Это репетиция обновления тестового центра, а не изменение рабочего эмитента. Регистрация организации, комиссия, пользователи и настройки менялись через интерфейс; 55 дополнительных черновиков для проверки пагинации создаются явно авторизованным HTTP в той же синтетической сессии. Оператору для обычного сценария SQL/CLI не нужны.

## Исправления и проверяемая причина

| Дефект | Исправление | Регрессия |
| --- | --- | --- |

## Границы доказательства

- 401 контролируемо вызывается удалением session cookie. Это настоящий отказ API и последующий login; восьмичасовое ожидание календарного истечения сессии не заявляется.
- Потеря ответа после finalize воспроизводится browser route после настоящего upstream commit. Это проверка восстановления при неизвестном результате, а не измерение WAN.
- Одностраничная история в конечном screenshot — результат фильтра. Переход на третью страницу и SHA оригинала проверяет исполнимый тест до фильтра.
- Импорт100 строк — измерение browser ввода/сопоставления. Оно не является benchmark генерации100 PDF.
- Длинные печатные поля, номера в физических ячейках PDF, Word/LibreOffice, юридическая и физическая приёмка находятся в отдельных доказательствах. Никакой browser PASS не заменяет их.
- `existing-suite.log`, `commercial-suite.log`, `final-suite.log`, `new-tests/` и `final/` относятся к диагностическим попыткам. Во время разработки Dev Fast Refresh прерывал сценарии; один финальный history selector был исправлен. Tracing на Windows зависал при дописывании trace.zip, поэтому окончательный полный набор выполняется с отключённой трассой, без skip тестов, с assertions/screenshots/JSON. Эти ранние прогоны не используются как release PASS.
