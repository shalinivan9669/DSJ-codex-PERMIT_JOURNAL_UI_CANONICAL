# Адресный предпросмотр: серверные изменения и проверки

Дата: 5 октября 2026 года. Базовый HEAD `0c91fafcb2ebffd415b2be42ca4c7166005eb93c`, изменения локальные, без коммита/публикации.

Добавлены отдельный `previewSchema` и `PreviewTarget`. Существующий endpoint принимает ASSIGNMENT по rowId/assignmentId или GROUP_PROTOCOL по eventId; finalizeSchema остаётся прежним. Без target сохраняются полные draft previews и выборочные директорские samples.

Выбор осуществляется только из tenant-scoped заявки/immutable proposal. Target проверяет точную revision; proposal требует proposalId+hash, scope и proposal revision. Сохраняются зависимости формы и все участники общего протокола. Адресный validation проверяет печатаемые поля, не блокирует документ из-за чужой строки, чужой ссылки на фото или ошибки другой формы. Ошибки сохраняют identity и исходный field path. Ошибки pinned issuer profile выбранного события сохраняются и для личного документа; отбрасываются лишь чужие события и поля самого группового протокола. Все данные читаются из сохранённого источника; preview не выдаёт номера, не создаёт issuance/IssuedDocument и не меняет draft/согласование.

Один target возвращает DOCX/PDF pair. Ключ включает источник/revision или proposal hash, идентичность формы/template version, человека/назначение, issuer и hash фактического renderInput. Sample/target одинаковой формы переиспользуют jobs. Фото ограничены выбранным человеком, что исключает изменение ключа из-за посторонних фотографий. Отсутствующий job пары восстанавливается; FAILED остаётся доступен через существующий /jobs/:id/retry.

Повтор адресного preview проверяет два готовых файла потоково (64 KiB, ограничение 5 секунд на файл): size и SHA256, путь внутри private store. SUCCEEDED с потерянным/повреждённым файлом или потерянной ссылкой возвращается в PENDING; old Artifact row сохраняется, новая генерация публикует новый immutable artifact. Только draft-preview jobs без issuance/document подлежат такому восстановлению. Проверка, не уложившаяся в лимит, возвращает восстанавливаемую 503 без необоснованного объявления файла повреждённым. Для отсутствующего job используется snapshot сохранившегося парного job, чтобы PDF worker находил правильный DOCX dependency.

Сохранённые generic PERSON titles больше не заменяются именем на каждом save. Список вычисляет название по человеку/компании; исторические пользовательские названия и raw draft titles сохраняются. Это предотвращает потерю ручного названия и превращение первого ФИО нового черновика в устаревающее сохранённое название.

Integration проверяет target вне samples, полный protocol roster, sample/target reuse, потерянный job пары и сохранённый DOCX dependency snapshot, FAILED retry, реально удалённый файл private store, повреждение bytes того же размера (SHA mismatch), переиспользование целого файла, неизменность Artifact rows, чужой tenant/request/target/proposal, неверный hash/revision, поздний рабочий draft, точные error paths, отсутствие изменения sequence/issuance/document/draft и generic/historical titles PERSON/COMPANY. Storage fault fixtures — специально созданные synthetic bytes для проверки файловой целостности, не доказательство визуально корректного PDF.

Дополнительный аудит 06.10.2026 обнаружил реальный пропуск: для закреплённой версии реквизитов курса проверялись лишь business rules, хотя личный renderer использовал именно эту версию. Общая подтверждённая версия могла скрыть неподтверждённую или непригодную к печати закреплённую. Теперь `validateDraft` проверяет и закреплённую версию; из технического draft без получателей берутся только ошибки `profile`/`profile.*`. Они сохраняют адрес `events.<id>.profile.*`, поэтому чужой курс не блокирует адресный preview. Выполнен RED→GREEN integration: неподтверждённые закреплённые реквизиты до исправления ошибочно допускались; после него обе проверки (`ISSUER_NOT_APPROVED`, `PRINT_UNBROKEN_VALUE` для 81 непрерывного символа) блокируют создание jobs/snapshots без мутации заявки и нумерации. Те же две ошибки другого курса остаются вне выбранного scope. Повтор integration 1/1 PASS, target unit 4/4 PASS, API typecheck, scoped ESLint, diff-check PASS; только disposable `demo_test_details_regression` и private `preview-profile-storage`. [Точное описание попыток](REGRESSIONS_RU.md), [структурированные проверки](integration.json).

В этой серверной подзадаче **не выполнялась браузерная визуальная проверка или открытие PDF/DOCX**. Эти проверки выполняются общим этапом приёмки, этот отчёт их не заменяет. Клиентский PDF.js recovery требует отдельной браузерной приёмки; факт успешного enqueue не подтверждает готовность файла.

Причина прежнего недоступного директорского предпросмотра, доказанная кодом и прежним unit test: `approvalPreviewSamples` выбирал одного реального человека на form/course/category, target отсутствовал. Для одинаковой формы у другого человека до выпуска не существовало адресного запроса. Встроенный просмотр PDF и скачивание DOCX — разные возможности; это отдельное ограничение представления, а не отсутствие назначенной формы. Ошибки jobs/storage/revision нельзя объявлять причиной конкретного пользовательского случая без его воспроизведения.
