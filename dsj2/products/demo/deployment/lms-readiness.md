# Подключение подтверждений для рабочего обучения

`compose.lms-evidence.yaml` — дополнительный файл для существующего Linux Compose-развёртывания. Он подключает настоящий закрытый файл подтверждений к сервисам `api` и `integration`. Подключение ещё не означает готовность: сервер проверяет содержимое для центра текущей сессии.

Override не применяется автоматически. В нём нет реквизитов оператора, одобрений или подготовленной разрешающей записи. Основные файлы запуска, образы, команды, сеть, БД и приватное хранилище не изменяются.

## Подготовить файл на выбранном сервере

1. Ответственный центра подтверждает реальные сведения о размещении, обработке, доступе, хранении и удалении данных. Состав записи описан в [инструкции восстановления](../docs/LMS_DEPLOYMENT_RECOVERY_RU.md) и [схеме](../packages/contracts/src/lms/deployment-gates.ts). Используйте точный `tenantId` своего центра из «Настройки → Пользователи → Доступ к обучению».
2. Сохраните UTF-8 JSON-массив подтверждённых записей размером не более 256 KiB **вне checkout, публичных каталогов и `/data/artifacts`**. Не используйте тестовый JSON из integration-тестов. Файл должен быть обычным файлом, доступным на чтение UID/GID `1000:1000`; рекомендуемый режим — `0400`, каталоги доступны только ответственному администратору и этому UID.
3. Задайте `DEMO_LMS_EVIDENCE_FILE` как абсолютный путь к этому существующему файлу на хосте. `DEMO_LMS_DEPLOYMENT_EVIDENCE` вручную задавать не нужно: override устанавливает постоянный путь внутри контейнера.

Для команд ниже нужны существующий закрытый env-файл этого развёртывания и настоящий файл подтверждений. В Linux shell задайте `DEMO_RUNTIME_ENV_FILE` и `DEMO_LMS_EVIDENCE_FILE` их абсолютными путями. Команды выполняются из корня `dsj2/products/demo`.

```sh
case "${DEMO_RUNTIME_ENV_FILE:-}" in /*) ;; *) exit 1 ;; esac
case "${DEMO_LMS_EVIDENCE_FILE:-}" in /*) ;; *) exit 1 ;; esac
test -f "$DEMO_RUNTIME_ENV_FILE" && test -f "$DEMO_LMS_EVIDENCE_FILE" || exit 1
export DEMO_LMS_EVIDENCE_FILE

docker compose --env-file "$DEMO_RUNTIME_ENV_FILE" \
  -f deployment/compose.yaml \
  -f deployment/compose.lms-evidence.yaml \
  config --quiet
```

`config --quiet` проверяет конфигурацию без вывода значений окружения и без запуска контейнеров. Пустая переменная пути отклоняется при разборе; `create_host_path: false` не позволяет Docker создать каталог вместо отсутствующего файла. Сохраняйте имя существующего Compose-проекта (`--project-name`, если оно задано) и все используемые TLS/host overrides в том же порядке; добавляйте этот файл последним.

## Подключить к существующему стеку

После проверки выбранного сервера и содержимого файла примените тот же набор Compose-файлов. Для базового стека команда такая:

```sh
docker compose --env-file "$DEMO_RUNTIME_ENV_FILE" \
  -f deployment/compose.yaml \
  -f deployment/compose.lms-evidence.yaml \
  up -d --no-deps --force-recreate api integration
```

Пересоздаются только два сервиса, читающих подтверждения. `api` проверяет запросы и подготовку документов; `integration` проверяет подготовку санитарных списков и продолжение выпуска. Render worker (`worker`) выполняет уже поставленные задания и этот файл не читает. Frontend, БД, ingress и административные профили также не получают файл. Дополнительный bind mount не заменяет существующий `/data` volume: Compose объединяет тома по пути назначения.

Откройте «Настройки → Пользователи → Доступ к обучению» и нажмите «Проверить настройку». Ожидается «Обучение доступно». Авторизованный `GET /api/settings/learning-readiness` должен вернуть `available: true, reason: "READY"`; `GET /api/ready` дополнительно проверяет БД, файлы и оба worker. Затем проверьте обычный вход методиста и преподавателя, программы, календарь и назначения. Один ответ `/health` не подтверждает готовность обучения.

При обновлении документа замените его на хосте безопасно и повторно пересоздайте `api` и `integration` той же командой: файловый bind mount может удерживать прежний файл после атомарной замены. Для удаления подключения пересоздайте эти сервисы с исходным набором Compose-файлов **без** `compose.lms-evidence.yaml`; данные обучения и документы не удаляются, операции, требующие подтверждений, снова блокируются.

## Railway и границы настройки

Этот override предназначен для Compose, а не для Railway. `deployment/railway/start.mjs` передаёт окружение дочерним процессам, но не создаёт и не загружает файл подтверждений. Фактическое размещение сервисов, резервных копий, временных файлов и проксируемого трафика проверяется отдельно; подстановка `KZ` не меняет инфраструктуру. Перенос существующих данных выполняется через [согласованный backup/restore](../docs/OPERATIONS_RU.md), а не через новый `setup` или сброс БД.

Правила Compose: [readonly bind mount](https://docs.docker.com/reference/compose-file/services/#volumes), [объединение файлов и томов](https://docs.docker.com/reference/compose-file/merge/#unique-resources).
