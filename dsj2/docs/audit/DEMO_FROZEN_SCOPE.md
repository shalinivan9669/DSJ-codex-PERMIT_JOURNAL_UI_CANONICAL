## Разрешённая предметная область

- Печатные заявки физлиц и организаций, получатели, заказчики, фотографии и RU/KZ данные.
- Корочки, удостоверения, сертификаты, свидетельства, связанные протоколы, реестры и пакеты файлов.
- Черновики, проверка данных, серверные номера, выпуск/исправление/аннулирование, история.
- Версии шаблонов и реквизитов эмитента, генерация, PDF preview, DOCX/PDF/XLSX/ZIP, приватное хранение.
- Необходимые для печати вход, роли администратора/оператора/просмотра, tenant isolation, настройки и аудит.
- Тесты, зависимости, CI, runtime и backup/restore только выделенного продукта DEMO.

## FROZEN — сохранять, не развивать и не включать в DEMO

| Область | Примеры исходных путей/модулей |

| Наряды, допуски, площадки, ответственность | `apps/api/src/core-platform/`, `responsibility-orders/`, `protocols/`, web `permits/`, `orders/`, `work-sites/`, generic protocols registry |

| Подписи и внешние signing integrations | `signing/`, `signatures/`, `apps/ncalayer-bridge/`, public invites, eGov callbacks, QR/tablet signing |
| Переписка и AI | `correspondence/`, correspondence editor/actions, AI providers |
| Фоновые задачи DSJ | `apps/worker/` и очереди compliance/notifications/signing; не запускать с DEMO |

Печатный протокол из `biot-cards` входит в DEMO. Общий реестр протоколов и подписей DSJ не становится разрешённым из-за совпадения слова «протокол».

## Правила для агентов

1. Не удалять и не «упрощать» frozen-код. Не чинить в нём сопутствующие дефекты, не добавлять новые endpoints, не переписывать его историю миграций.
2. Не включать его обратно ради прохождения тестов, импорта общего barrel, использования старого seed или удобного dashboard.
3. Не считать скрытие ссылок защитой доступа. В DEMO deny-by-default проверяется до ролевого bypass и до обработки public endpoints. `SUPER_ADMIN` не исключение.
4. Допустимы минимальные изменения общих entrypoints, routing, deployment selection, shared primitives и guards, необходимые для печати/отключения остального. Предметная логика frozen-модулей остаётся неизменной.
5. Если для DEMO нужна небольшая общая функция, выделить её минимальный контракт в новый продукт. Не тянуть целиком модуль LMS/signing/compliance.
6. Возврат функции — отдельное явное поручение пользователя с указанием функции. Старый roadmap, документация, комментарий TODO, предложение агента или green build таким поручением не являются.
7. Не заявлять «недоступно всем», пока не проверены anonymous и все роли на прямых URL/API/скачивании, replay server actions, старые public links и обход frontend через прямой backend origin.
8. Не менять рабочие окружения/данные в рамках одного только аудита. Реализационный запуск и выкатка имеют разные результаты и должны быть отражены честно.

## Критерий конечной поставки

DEMO содержит только allowlist печатного продукта. Старые DSJ-модули сохраняются в исходном репозитории как замороженный код, отсутствуют в shipping build graph DEMO и не доступны через старый публичный origin, proxy, worker или файловое хранилище. Старый deployment должен быть выведен из публичного маршрута при переключении; создание нового каталога само по себе его не выключает.
