# DEMO — аудит печати, данных и автономного выделения

Дата проверки: 22.09.2026. Проверка исходников и локальных генераторов; БД, миграции, seed, внешние API и рабочие данные не запускались. Название самостоятельного продукта — DEMO. Отдельное требование к маркировке тестовых документов не следует выводить из названия DEMO.

## Что реально найдено

В DSJ работает контур `biot-cards`, а не описанный в передаче отдельный продукт с `PrintRecord` и Company Workspace. Его сущности — `CardGenerationRequest` и `CardGenerationRequestItem` (`packages/database/prisma/schema.prisma:657`, `:684`). Запись содержит company, автора, тип, дату, номера, сведения слушателей и base64-фото. Статуса черновика/финализации, версии, выделенного реестра номеров, generation job и сохранённого файла у этих сущностей нет.

Форматы проверены по действующему `apps/api/src/biot-cards/biot-cards.service.ts`, а не README, который устарел.

Подтверждения: конфигурация типов `service.ts:109–169`; фото `:172–203`, `:453–461`; варианты комплекта `:673–724`; DOCX single/batch `:3220–3267`; экспорт реестра `:3006–3049`; приоритет первого вывода `:4110–4114`. PDF-конвертация, PDF-preview, ZIP полного комплекта и фоновая печать в этом контуре не найдены. Слово preview в именах относится к объединённому DOCX. Указанные сроки действия — факт кода, их нормативная правильность этим аудитом не подтверждается.

## Подтверждённые дефекты и недостающие гарантии

1. **Нумерация допускает конфликт и повторное использование.** `service.ts:1956–1971` загружает лишь последние 1000 AuditLog всех типов; фильтрация нужного направления идёт после ограничения. `:3477–3488` вычисляет max+1, `:2164–2279` проверяет занятость по этим же логам. Номера присылает клиент (`packages/types/src/document.ts:335–338`); в модели item нет уникального ограничения на номер (`schema.prisma:684–711`). Два одновременных запроса могут пройти проверку; старые номера выпадают из окна. Для DEMO нужны транзакционный счётчик и реестр с уникальностью tenant + направление + вид документа + серия/год по согласованному правилу. Номер присваивается при финализации; обычное редактирование его не меняет. Приёмка: параллельные финализации и повтор одного idempotency key дают один выпуск, номера не повторяются после удаления/аннулирования, выборка 1000 записей ни на что не влияет.

2. **Ошибка генератора оставляет заявку как будто выпущенной.** `service.ts:4099–4114` сначала создаёт заявку, затем пишет `biot_card.generated` для каждой строки и только потом рендерит. Нет общей транзакции, статуса generation failed и idempotency key. Клиент при потере ответа может получить конфликт вместо ссылки на уже созданную заявку; ошибка логирования оставляет частичное состояние. Решение: транзакция snapshot + finalization + issuance + durable job; отдельные READY/FAILED/RETRYING для артефактов; результат можно получить после повторного запроса без нового номера.

3. **Повторное скачивание меняет исторический документ.** `service.ts:3100–3267` берёт текущие данные заявки и текущий DOCX-файл шаблона; `:1842–1850` читает временный результат и удаляет его. Нет сохранения output bytes/hash/template version/render policy. Изменение шаблона меняет ранее выданный документ при том же номере. Решение: immutable snapshot + template hash/version + rendered artifact hash + private storage; download возвращает сохранённый artifact. Новое исправление — новая версия, связь с предшественником и причина.

4. **Исправление/удаление уничтожает доказательную историю.** `service.ts:2803–2838` заменяет все строки и удаляет старые generation logs; `:2855–2907` физически удаляет историю заявки и саму заявку; `:3958–3982` удаляет логи по номерам. Это дополнительно освобождает номера. Решение: append-only audit, optimistic revision для черновика, после выпуска только correction/annul/reissue. Старый snapshot, файлы и зарезервированные номера сохраняются. Приёмка: две вкладки не перезаписывают друг друга, исправление не меняет скачивание старой версии.

5. **История обрывается на 50 заявках.** `service.ts:2647–2688` имеет `take: 50` без cursor/пагинации и поиска. Оператор не найдёт более ранние выпуски обычным списком. Для DEMO нужны поиск по номеру/слушателю/заказчику/дате, cursor pagination, total/filter state, индексы tenant + relevant search fields. Приёмка на 10 000+ синтетических заявок с доступом к первой и последней.

6. **Шаблоны и смысловые значения принадлежат прежнему центру.** `service.ts:224–260` содержит конкретные комиссии/подписантов и литералы старых приказов; `:273–275` фиксирует организацию и 5 дней обучения; `:1604–1618` фиксирует дисциплины и оценки Хорошо/Жаксы. В 9 из 11 физических DOCX-шаблонов найден текст Стандарт; один из этих 11 (`ps-certificate-template.docx`) не подключён к действующим путям. Реально сгенерированные BIOT/PB сохраняют старый центр и подписи. Переименование интерфейса в DEMO этого не устраняет. Решение: issuer profile отдельно от customer company; версии согласованных форм, явные комиссия/основание/результат/даты; запрет выдачи при обязательном незаполненном реквизите; синтетический профиль для демонстрации. Растровые логотипы/подписи требуют отдельного осмотра: XML не доказывает их отсутствие.

7. **XLSX formula injection воспроизведена.** `scripts/export_card_request_registry.py:103–112` присваивает пользовательские строки непосредственно ячейкам. Синтетическое ФИО `=1+1` стало ячейкой `Реестр!D2` с `data_type=f`. Решение: писать пользовательские значения как литеральный текст и проверять все экспортируемые поля; тесты `=`, `+`, `-`, `@`, whitespace-prefix для поддерживаемых spreadsheet viewers. Вредоносные данные не исполнялись; использована только безопасная формула `=1+1`.

8. **Печать держит HTTP-запрос и не ограничена по времени/ресурсам.** `service.ts:1791–1840`, `:3773–3827` запускают child process без timeout/abort/ограничения stderr; общий документ целиком находится в памяти. Контракт допускает 100 × 6 млн символов фото (`packages/types/src/document.ts:273–278`, `:333–354`), не имея отдельной модели upload. Решение: ограниченные uploads с проверкой реального формата и размеров, refs на фото; worker с lease/fencing, concurrency/memory/time limits, retries и terminal failure; partial bundle status по каждому файлу. В контейнер добавить закреплённые Python-пакеты, PDF engine и шрифты RU/KZ.

9. **Печатный контур нельзя выпускать на предположении о целостности всей DSJ schema.** Статическое сравнение обнаружило 75 Prisma models и 44 CREATE TABLE по всем migration.sql; для 31 модели не найден CREATE TABLE, включая Organization, DocumentEnvelope/Version, RetentionPolicy. Это сигнал неполной истории, а не результат `migrate deploy`: live БД не проверялась. Отдельному DEMO нужен собственный минимальный baseline, прогон с пустой БД, schema diff и отдельный legacy importer с dry-run/reconciliation. Применённые DSJ migrations не переписывать.

10. **Worker DSJ не является печатным worker.** `apps/worker/src/main.ts` занимается compliance/reminders/signing/work permits, не document generation. Перенос целого файла принесёт посторонние процессы. В нём также есть неатомарный claim уведомления (`:525–551`), нет восстановления processing после crash, EMAIL всегда failed (`:555–575`); stale callbacks переводятся в IGNORED (`:649–678`). Эти дефекты не следует включать в доработку DEMO как отдельный scope: отдельный generation worker должен иметь правильные гарантии с начала.

## Граница выделения

Текущая цепочка: Next page `/certificates/biot-experimental` → `biot-card-generator.tsx` → web proxy `/api/biot-cards/*` → Nest `BiotCardsController` → `BiotCardsService` → shared schemas + tenant-scope + Prisma + AuditService + runtime/workspace helpers → Python scripts → DOCX templates. В service employee/training enrichment опционален (`:3583–3597`), обязательной зависимости печати от LMS нет.

Переносить: преобразования RU/KZ, уже работающие DOCX-подстановки, фото-слоты, формы, enum mapping, форматные регрессии. Перепроектировать: workflow, номера, версии, persistence/jobs/storage, центр/комиссии, поиск, API responses. Изолировать через importer: прежние Employee/ContractorCompany/TrainingAssignment. Не переносить: DSJ journal/signing/eGov/work permits/compliance/learning/exams/correspondence и их worker.

Для независимого `products/demo` достаточно tenant/issuer, users/membership, customer company/person, request/draft rows, immutable issuance/version snapshot, number counter/ledger, template version, generation job/artifact, append-only audit и photo references. Tenant учебного центра и компания-заказчик должны быть разными сущностями. Состояния «сохранено», «финализировано», «файл готов», «выдано» должны оставаться различимыми; техническая генерация не равна подписи или фактической выдаче.

PostgreSQL durable job table с atomic claim, leaseUntil, attempts, idempotency и fencing достаточна для первой автономной версии. Не нужно добавлять Redis только из-за DSJ. Artifact storage за интерфейсом: приватный durable volume в одном экземпляре, безопасные object keys и tenant-authorized download; возможность S3-compatible adapter. DB + volume + encryption/secrets backup должен проверяться restore drill, включая сравнение hash всех тестовых файлов; зафиксировать измеренные RPO/RTO. Если несколько worker/replicas, выбранное хранилище должно реально быть общим, local ephemeral disk не подходит.

## Выполненная проверка и границы результата

- `DEMO_print_smoke.py` выполнил четыре генерации: BIOT одиночный, BIOT batch на 2 слушателя с длинным ФИО и казахскими буквами, PB с валидным синтетическим PNG, PS witness. Все exit 0. XML содержит синтетические ФИО и казахские буквы; PB содержит новый media object; внешних mail-merge relationships нет.
- XLSX probe успешно воспроизвёл formula interpretation.
- Существующий `biot-cards.namespace-regression.test.ts` запущен повторно с bundled Python: **3 tests, 3 pass, 0 fail, 0 skip**. Один тест прогоняет single + multi paths по восьми card/protocol шаблонам. Это структурные проверки OOXML, они не проверяют визуальную вёрстку и используют в одном тесте невалидные mock PNG bytes.
- `render_docx.py` попытался отрендерить BIOT; ошибка `LibreOffice soffice.exe was not found on PATH`. Визуальная проверка страниц, Word/LibreOffice совместимость, переносы длинных ФИО, физические размеры удостоверений, печать фото и качество PDF **не подтверждены**.
- БД, API end-to-end, конкурентная финализация, падение worker, повторный запуск, retention/backup restore и миграция legacy данных не запускались. Эти проверки являются обязательными критериями приёмки будущей реализации.

Доказательства: `docs/audit/DEMO_print_smoke/DEMO_smoke_results.json`, `DEMO_template_inventory.json`, DOCX и XML-derived text files в этой же папке. Генератор проверки — `docs/audit/DEMO_print_smoke.py`. Эти файлы предназначены для внутреннего аудита, не являются согласованными формами DEMO для выдачи клиентам.
