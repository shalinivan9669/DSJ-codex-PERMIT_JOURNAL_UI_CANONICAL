6. ЧЕРНОВИКИ, ФИНАЛИЗАЦИЯ И НОМЕРА

Сохраняй неполный черновик на сервере без финальных номеров. PATCH требует expectedRevision. В интерфейсе — autosave, явное сохранение и состояния сохранения/ошибки/конфликта. Не более одного PATCH в полёте; новые изменения ждут следующего сохранения. Перед validate/preview/finalize дождись сохранения последних введённых символов. Старый ответ не перезаписывает новое локальное состояние.

Финализация — одна транзакционная команда: права/tenant/revision/валидация → immutable snapshot → документы → резервы номеров → audit → durable generation jobs → сохранённый результат идемпотентной операции. Файлы внутри транзакции не рендерить.

Закрепи UNIQUE(tenantId, command, idempotencyKey) и уникальность выпуска requestId + sourceRevision. Хэш команды включает requestId, revision и payload. Один ключ с теми же данными возвращает прежний результат, с другими — 409. Два ключа для одной revision не создают два выпуска. Потеря ответа после commit безопасна при повторе.

Нумерация только backend/DB, атомарно, без runtime max+1, AuditLog и клиентского счётчика. Стабильный namespace: эмитент/tenant + направление + kind, с серией/годом только по явной политике. Версия профиля или policy не создаёт новый namespace и не сбрасывает счётчик. Уникальность защищает sequence и форматированный номер. Протокол, удостоверение и дополнительные номера ПС имеют корректные отдельные области.

Preview/save/download/PDF/retry не расходуют номера. Отменённые номера не переиспользуются. Внешний номер основания хранится отдельно. Историческое число 12000 не делай глобальным началом. Даты обучения, протокола, документа и технического создания различаются; date-only не сдвигается из-за UTC, «сегодня» определяется timezone центра. Невалидная дата не подменяется текущей.

7. ГЕНЕРАЦИЯ, ФАЙЛЫ И ИСТОРИЯ

Отдельный render-worker с PostgreSQL durable job table: atomic claim, lease, heartbeat, fencing token, ограниченные retries/backoff, concurrency, timeout, bounded logs, корректное завершение дочерних процессов и shutdown. Не тащи DSJ worker и Redis только ради печати.

Worker получает неизменяемый render snapshot. Для preview это draft revision + template/profile versions без выпуска и номера; для рабочего файла — зарегистрированный issuance. Устаревший preview помечается в UI.

Приватное постоянное хранилище: durable volume за ArtifactStore для одного узла; при разных хостах — действительно общее хранилище. Никаких originals только в tmp/эфемерном контейнере.

У готового файла есть bytes, size, sha256, версия шаблона/renderer и связь с документом. Storage keys неизменяемые, по content hash/attempt; опубликованные bytes не перезаписываются. Canonical artifact выбирается DB CAS с актуальным fencing token. Устаревший worker не может испортить готовый файл даже при потере lease.

Повторное скачивание отдаёт сохранённые bytes. Изменение справочника/шаблона не меняет историю. Зарегистрированные данные нельзя тихо обновить или удалить: исправление/отмена — отдельная связанная операция с причиной; старый snapshot и файл сохраняются. Не удаляй audit events.

Сбой после регистрации оставляет честный FAILED/PARTIAL job; повторяет генерацию, а не выдачу номеров. Показывай X из Y, сохраняй готовые результаты, повторяй только неудачные. ZIP содержит manifest; неполный комплект явно обозначен.

Очистка preview/orphan uploads не удаляет final artifacts, связанные фото, версии шаблонов, объекты активного lease или backup. Проверь гонки cleanup/finalize/retry.

Фото загружаются отдельно и передаются как assetId. Декодируй PNG/JPEG, проверяй байты/пиксели/размер, безопасно перекодируй, поддержи crop/rotation и preview. Согласуй лимиты UI/proxy/API/schema; массовые base64 в JSON убери. Не публикуй приватные изображения по угадываемым URL.

Ведущие нули, Unicode и номера строк сохраняются. Повтор импорта безопасен; частичные строки не исчезают; превышение лимита видно до регистрации. История — серверный поиск, фильтры, pagination/total; полная выгрузка не ограничивается текущей страницей. Не загружай все фото/строки в list response. Устрани запросы defaults на каждую строку и выбрасываемые binary responses.

Раздели большой компонент и сервис по обязанностям, сохрани один источник правил. Сделай loading/disabled/errors/retry, фокус первой ошибки, labels, dialog focus/Escape, keyboard flow и удобную таблицу на 1366×768/1920×1080. На узком экране обязательные действия остаются доступными.

9. ПЕРЕНОС, СБОРКА И ЭКСПЛУАТАЦИЯ

Рабочую БД DSJ, выданные документы, применённые migrations и реальные подписи не меняй. Не запускай destructive seed или db push вместо миграций. Новые migrations проверяй на отдельной disposable БД: empty install и upgrade.

Подготовь read-only legacy export/import с dry-run, повторяемостью по source IDs, counts/checksums и отчётом конфликтов. Не перенумеровывай и не объединяй людей по ФИО молча. Отсутствующий оригинальный файл не объявляй восстановленным: реконструкция имеет отдельное происхождение.

Собственная сборка DEMO — frozen lockfiles, поддерживаемые исправленные зависимости, pinned Python/converter/fonts, non-root containers, private volumes, health/readiness, limits и graceful shutdown. Повтори актуальный dependency audit, исправь применимые high/critical; не делай слепое force-update и не ремонтируй замороженное дерево ради показателя.

Backup охватывает БД, файлы, шаблоны, фото и необходимые настройки/ключи безопасным способом. Выполни restore в пустую среду и сравни counts/hashes. Логи — без паролей, токенов, фото и полных персональных payload; ошибки имеют correlation ID.

Разрешаю локальную реализацию, установку зависимостей, тестовые сервисы/изолированные БД, сборку, проверки и подготовку deployment. Без отдельного поручения на конкретное рабочее окружение не применяй production migrations, не переключай реальный трафик и не останавливай внешние рабочие сервисы. Подготовь конкретный cutover/rollback; rollback не должен терять новые выпуски или открывать замороженные модули.
