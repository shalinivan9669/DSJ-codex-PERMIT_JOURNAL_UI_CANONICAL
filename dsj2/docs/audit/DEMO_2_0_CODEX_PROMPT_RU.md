# DEMO 2.0 — готовый запрос для одного реализационного запуска Codex

Реализуй **DEMO 2.0** по единому плану `dsj2/docs/audit/DEMO_2_0_IMPLEMENTATION_PLAN_RU.md`, опираясь на подтверждённый аудит `dsj2/docs/audit/DEMO_2_0_AUDIT_RU.md` и правила `dsj2/docs/audit/DEMO_FROZEN_SCOPE.md`.

Моя цель — самостоятельная рабочая программа только для подготовки и печати корочек, сертификатов, удостоверений, свидетельств, связанных протоколов и реестров. Название приложения **DEMO**. Не называй продукт прежним названием из передачи контекста.

Выполни весь план за один реализационный подход: от границы продукта и модели данных до готового интерфейса, файлов, тестов и документации. Не дели результат на P0/P1/P2, не ограничивайся каркасом, новым меню или перечнем советов. Внутренний последовательный порядок работ и параллельные агенты разрешены; пользователю не нужно запускать каждую часть отдельно.

Перед изменениями:

1. Прочитай wrapper `AGENTS.md`, `dsj2/AGENTS.md`, routing `.mempalace/index.json`, ближайшие area instructions и указанные audit/plan/freeze документы.
2. Проверь текущие branch/HEAD/status и сравни с audited commit `161c5ed022c9e2c643e80802d3f9dc2cd496a041`. Сохрани мои незакоммиченные изменения. Создай `codex/demo-print-2-0`, если такой рабочей ветки ещё нет.
3. Учитывай приложенные старые промпты как исторический контекст. Не исполняй их планы LMS или юридических интеграций и не выдумывай отсутствующие PrintRecord/worker/PDF функции.

Обязательные границы:

- Всё, что не относится к печатному продукту, сохранить в исходниках и данных, но сделать недоступным всем пользователям, включая администратора/SUPER_ADMIN. Закрыть меню, прямые страницы, API, server actions, скачивания, public links и непечатные фоновые задания. Скрытые ссылки сами по себе не выполняют задачу.
- Непечатные DSJ-модули заморожены. Не рефакторить, не исправлять их попутно, не удалять и не активировать без отдельного явного поручения. Сохрани эту границу в AGENTS и автоматических проверках импортов/маршрутов.
- Создай автономный workspace `dsj2/products/demo/` по плану. В нём не должно быть runtime-зависимости от DSJ БД, `@dsj/*`, полной AppModule, DSJ worker, LMS, кабинетов, NCALayer/eGov или generic core-platform.
- Для изоляции допускаю необходимые изменения центральных entrypoints, routing, auth transport, guards, печатной оболочки и deployment selection, описанные в плане. Не меняй предметную логику замороженных модулей.
- В рамках создания DEMO поручаю необходимые изменения её auth/session/tenant isolation, схемы данных, нумерации, очереди генерации, приватного хранения, runtime/deployment manifests и тестов. Это явная область реализации, а не просьба только переименовать интерфейс.
- Не изменяй действующие данные, применённые DSJ migrations и реальные подписи/выданные документы; не запускай destructive seed. Миграционные тесты выполняй на отдельной disposable БД, legacy import сначала dry-run.
- Подготовь полный deployment/cutover/rollback, но без отдельного поручения на конкретное рабочее окружение не выполняй production rollout. Не обещай закрытие прежнего публичного DSJ, если его ingress/workers фактически не проверены.

Ключевые свойства реализации:

- Серверный черновик без финальных номеров; optimistic revision и восстановление после refresh.
- Одна атомарная идемпотентная финализация, серверная конкурентная нумерация с DB constraints; повтор не создаёт новый комплект.
- Неизменяемый snapshot выпуска и версии шаблона/эмитента; исправление с причиной; append-only audit.
- Отдельный render-worker и durable PostgreSQL jobs с lease/fencing/retry; Python/converter с ограничениями; номера не меняются при retry.
- Сохранённые приватные bytes DOCX/PDF/XLSX/ZIP и hashes; повторное скачивание прежнего файла, честный статус частичного результата.
- Сохранение всех найденных форм BIOT/PTM/PB/PS, языков, фото и связанных протоколов. Предметные значения и геометрию не терять в редизайне.
- Независимые RU/KZ имена и названия; никаких неявных оценок/результатов обучения или прежнего центра в документах. DEMO — имя приложения, эмитент берётся из настроек.
- Полноценные импорт с preview/ошибками/защитой от повторов, история с поиском и пагинацией, безопасный XLSX export.
- Лёгкий desktop-first интерфейс «Заявки · Заказчики · История · Настройки», без непечатных кабинетов. Полный путь человека и компании, клавиатура, focus/errors, фото/crop, preview.
- Воспроизводимые зависимости, реальный lint, migrations, integration/e2e/render tests, backup/restore.

Работай до готового результата. Рутинные обратимые решения в этих границах принимай самостоятельно. Если чего-то не хватает во внешнем окружении, продолжай все независимые работы, подготовь конкретное воспроизведение и честно обозначь блокировку; не подменяй отсутствующий прогон mock-успехом.

Выполни приёмочную матрицу A01–A50 из плана и устрани обнаруженные дефекты. Существующий green `pnpm verify` DSJ не является приёмкой DEMO. Требуемые print tests в CI не должны молча skip из-за отсутствующего Python/LibreOffice. Проверь настоящие файлы на уровне всех страниц, а не только валидность DOCX ZIP/XML.
